## Highlights

- Go 1.26 is now the minimum supported Go version [#1326](https://github.com/apache/arrow-go/pull/1326)

### Arrow

#### Features

- Added a scalar aggregate framework to the compute package, starting with the `count` and `sum` kernels [#1336](https://github.com/apache/arrow-go/pull/1336)
- Added the `starts_with` compute function, including `string_view`/`binary_view` inputs, `IgnoreCase`, and the Substrait `starts_with` mapping used by
iceberg-go prefix row filters [#1448](https://github.com/apache/arrow-go/pull/1448), [#1467](https://github.com/apache/arrow-go/pull/1467), [#1468](https://github.com/apache/arrow-go/pull/1468)
- Added `SortKey.FloatTotalOrder` to sort floats by IEEE 754 totalOrder, distinguishing `-0`/`+0` and signed NaNs [#1430](https://github.com/apache/arrow-go/pull/1430)
- Added `Decimal32`, `Decimal64`, `StringView` and `BinaryView` scalar types [#1501](https://github.com/apache/arrow-go/pull/1501), [#1490](https://github.com/apache/arrow-go/pull/1490)
- Added `ipc.WithZstdLevel` to choose the zstd compression level of IPC writers [#1376](https://github.com/apache/arrow-go/pull/1376)
- Added `Reader.ContinueFrom` to resume an IPC reader on a stream that arrives as several blobs, a pattern that stopped working in v18.8.0 [#1346](https://github.com/apache/arrow-go/pull/1346)
- The Flight SQL `database/sql` driver now accepts `grpc+tcp://`, `grpc+tls://` and `grpc+unix://` DSNs [#1420](https://github.com/apache/arrow-go/pull/1420)
- The JSON and CSV readers expose their input offset to help locate decoding errors [#1342](https://github.com/apache/arrow-go/pull/1342)

#### Bug Fixes

- `is_null`, `is_not_null` and `not` returned wrong masks for sliced arrays, dictionaries with null values, and null, union and run-end encoded arrays, so
filters could silently keep or drop the wrong rows. `is_null` now also honors `NullOptions.NanIsNull` [#1456](https://github.com/apache/arrow-go/pull/1456),
[#1458](https://github.com/apache/arrow-go/pull/1458), [#1461](https://github.com/apache/arrow-go/pull/1461), [#1465](https://github.com/apache/arrow-go/pull/1465), [#1488](https://github.com/apache/arrow-go/pull/1488)
- `NewDatumWithoutOwning` now returns a non-owning Datum; previously `Release()` freed the caller's memory [#1377](https://github.com/apache/arrow-go/pull/1377)
- `and_kleene` and `or_kleene` returned `false` instead of null when `ExecCtx.ChunkSize` was smaller than the input [#1306](https://github.com/apache/arrow-go/pull/1306)
- A cancelled `CallFunction` no longer returns a result with a nil error, and the default `NumParallel` follows the cgroup-aware `GOMAXPROCS` in
containers [#1410](https://github.com/apache/arrow-go/pull/1410), [#1384](https://github.com/apache/arrow-go/pull/1384)
- Fixed generated assembly that clobbered the frame pointer or Go's reserved registers, breaking profilers and frame-pointer unwinders, in the amd64 compute
kernels and the Parquet bit-unpacking and Bloom filter kernels [#1432](https://github.com/apache/arrow-go/pull/1432), [#1300](https://github.com/apache/arrow-go/pull/1300), [#1379](https://github.com/apache/arrow-go/pull/1379)
- Decimal rescaling no longer panics or returns wrong values, infinite decimal strings are rejected, and scales past `MaxScale` fail clearly [#1307](https://github.com/apache/arrow-go/pull/1307),
[#1409](https://github.com/apache/arrow-go/pull/1409), [#1513](https://github.com/apache/arrow-go/pull/1513), [#1514](https://github.com/apache/arrow-go/pull/1514), [#1515](https://github.com/apache/arrow-go/pull/1515)
- The C Data interface exports extension arrays as their storage and imports zero-length fixed-size lists, such as those returned by DataFusion [#1526](https://github.com/apache/arrow-go/pull/1526),
[#1308](https://github.com/apache/arrow-go/pull/1308)
- `arrow.TypeEqual` now compares `LargeListType` like `ListType`, so `array.Concatenate` no longer rejects identical large list types [#1440](https://github.com/apache/arrow-go/pull/1440)
- `NewMappedFileReader` no longer panics on dictionary fields, and Flight SQL `ExecuteIngest` sends the schema for empty inputs [#1365](https://github.com/apache/arrow-go/pull/1365),
[#1433](https://github.com/apache/arrow-go/pull/1433)
- The JSON record reader no longer swallows an unexpected EOF on truncated input [#1341](https://github.com/apache/arrow-go/pull/1341)

#### Performance Improvements

Performance remains a major theme: 51 of the merged pull requests are dedicated
optimizations. Unless noted otherwise, the figures below are the PR-reported
benchmarks on an Apple M1 Pro.

- Bulk array comparisons: comparing an array without a validity bitmap against one with a materialized bitmap is up to 414x faster for booleans (8.8ms to 21.3us
over 1M values) and 15.3x for int64, and all-valid list equality over 65,536 rows drops from 17.8ms to 0.197ms [#1327](https://github.com/apache/arrow-go/pull/1327),
[#1330](https://github.com/apache/arrow-go/pull/1330), [#1347](https://github.com/apache/arrow-go/pull/1347)
- SIMD filtering now covers 8-, 16- and 64-bit types: 1M-element alternating int64 filters go from 3.97ms to 0.45ms (8.7x), int16 from 4.23ms to 225us, and
8-bit alternating masks run 22-24x faster. AVX2 take-index compaction adds up to 4.5x on AMD EPYC [#1311](https://github.com/apache/arrow-go/pull/1311),
[#1349](https://github.com/apache/arrow-go/pull/1349), [#1350](https://github.com/apache/arrow-go/pull/1350), [#1348](https://github.com/apache/arrow-go/pull/1348)
- `SortIndices` radix-sorts single-chunk, null-free integer columns: 65,536 random int64 values sort in 1.31ms instead of 12.3ms [#1391](https://github.com/apache/arrow-go/pull/1391)
- Dictionary-heavy workloads: `unique` over 256 chunks with changing dictionaries is 36.6x faster (60.0ms to 1.64ms) with 98.5% fewer bytes allocated,
concatenating chunks that share a dictionary drops from 82.4us to 3.7us, and builders reuse unchanged dictionaries, cutting the per-row cost of
small-batch dictionary reads through `pqarrow` by up to 93% [#1395](https://github.com/apache/arrow-go/pull/1395), [#1403](https://github.com/apache/arrow-go/pull/1403), [#1444](https://github.com/apache/arrow-go/pull/1444)
- Bitmap utilities: `AppendBools` takes 88% less time (geometric mean), unaligned bitmap operations are up to 11.4x faster, and misaligned bitmap equality and
unaligned transfers improve 6.5x and 5.4x (geometric means) [#1402](https://github.com/apache/arrow-go/pull/1402), [#1437](https://github.com/apache/arrow-go/pull/1437),
[#1414](https://github.com/apache/arrow-go/pull/1414), [#1416](https://github.com/apache/arrow-go/pull/1416)
- IPC zstd compression: pooled decoders cut decompression time by 69-78% for buffers up to 256KiB per column, and pooled encoders take a writer-per-record
workload from 246.4us to 4.5us and from about 2.2MiB to 7.1KiB allocated per op (Apple M2 Pro) [#1331](https://github.com/apache/arrow-go/pull/1331), [#1429](https://github.com/apache/arrow-go/pull/1429)
- Full-file CSV reads stream into builders: 1.69x faster with 71% fewer bytes allocated [#1393](https://github.com/apache/arrow-go/pull/1393)

### Parquet

#### Features

- Added opt-in ALP (Adaptive Lossless floating-Point) encoding for FLOAT and DOUBLE columns, interoperable with Arrow C++. Writers enable it with
`WithALPEncoding`; reading needs no option [#1289](https://github.com/apache/arrow-go/pull/1289)
- Added an optional `parquet/encryption` package with KMS support, so files encrypted by pyarrow's `CryptoFactory` (PKMT1 key material, single or double
wrapping) can be read through `KmsKeyRetriever` [#1478](https://github.com/apache/arrow-go/pull/1478)
- Write geospatial statistics (bounding box and geometry types) for GEOMETRY column chunks, and `null_count` statistics for GEOMETRY and GEOGRAPHY [#1504](https://github.com/apache/arrow-go/pull/1504),
[#1533](https://github.com/apache/arrow-go/pull/1533)

#### Bug Fixes

- Encryption interoperability: read encrypted files written by parquet-mr (Spark, Hive, Iceberg on parquet-java), preserve `AES_GCM_CTR_V1` in plaintext
footers, and return an error instead of panicking on columns without a key [#1390](https://github.com/apache/arrow-go/pull/1390), [#1412](https://github.com/apache/arrow-go/pull/1412), [#1406](https://github.com/apache/arrow-go/pull/1406)
- `pqarrow` wrote wrong data for sliced `FixedSizeList` columns and for `FixedSizeList` columns spanning more than one row group [#1382](https://github.com/apache/arrow-go/pull/1382)
- Encoders no longer carry stale state across pages: RLE boolean columns repeated earlier values on later pages, plain boolean and delta encoders wrote
pre-`Reset` state, and all-null `DELTA_BINARY_PACKED` pages were padded with zeros [#1539](https://github.com/apache/arrow-go/pull/1539), [#1545](https://github.com/apache/arrow-go/pull/1545),
[#1546](https://github.com/apache/arrow-go/pull/1546), [#1400](https://github.com/apache/arrow-go/pull/1400)
- Statistics: V2 data pages no longer report zero nulls without page statistics, byte array statistics written from Arrow count empty strings, and
`UpdateSpaced` counts non-null values from the validity bitmap [#1543](https://github.com/apache/arrow-go/pull/1543), [#1527](https://github.com/apache/arrow-go/pull/1527), [#1367](https://github.com/apache/arrow-go/pull/1367)
- Fixed a memory leak in DELTA decoders, and dictionary-encoded boolean columns now return an error instead of panicking [#1394](https://github.com/apache/arrow-go/pull/1394),
[#1547](https://github.com/apache/arrow-go/pull/1547)

#### Performance Improvements

- Reading dictionary-encoded columns allocates the dictionary up front again, fixing an allocation regression introduced in v18.8.0 [#1473](https://github.com/apache/arrow-go/pull/1473)
- Bloom filter hashing pools its scratch buffers: hashing 64 values drops from 5.52us to 311ns, and dictionary Bloom filter writes take up to 32% less time
(Intel Core Ultra 7 155H) [#1378](https://github.com/apache/arrow-go/pull/1378)
- Level and boolean decoding: nullable boolean bitmap expansion takes 85% less time (geometric mean), 1-bit packed levels decode in 55-60% less time, all-true and
all-false RLE booleans decode 66-98% faster (amd64), and narrow RLE literal levels encode 2.25-2.61x faster [#1405](https://github.com/apache/arrow-go/pull/1405),
[#1404](https://github.com/apache/arrow-go/pull/1404), [#1417](https://github.com/apache/arrow-go/pull/1417), [#1419](https://github.com/apache/arrow-go/pull/1419)
- Dictionary encoding: indices are encoded in RLE batches (65,536 constant indices drop from 187.7us to 26.0us), and FLBA and Int96 dictionary insertion is
29-33% faster with up to 50% fewer allocations [#1328](https://github.com/apache/arrow-go/pull/1328), [#1312](https://github.com/apache/arrow-go/pull/1312)
- DELTA encodings: constant `DELTA_BINARY_PACKED` blocks decode 2.1x faster, `DELTA_LENGTH_BYTE_ARRAY` decodes 1.62-2.00x and discards 2.43-2.74x faster,
`DELTA_BYTE_ARRAY` prefix matching is up to 4.7x faster (AMD EPYC), and its discard path drops from 65,535 allocations to none [#1396](https://github.com/apache/arrow-go/pull/1396),
[#1415](https://github.com/apache/arrow-go/pull/1415), [#1388](https://github.com/apache/arrow-go/pull/1388), [#1321](https://github.com/apache/arrow-go/pull/1321)
- Reads: optional columns use dense decoding for batches without nulls (up to 45% faster per row on AMD EPYC), and serial reads build struct child readers
without goroutines, 37-43% faster (Apple M4 Max) [#1447](https://github.com/apache/arrow-go/pull/1447), [#1434](https://github.com/apache/arrow-go/pull/1434)
