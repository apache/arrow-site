## Highlights

### Arrow

#### Features

- Added `VariantGet` for efficient path extraction from variant arrays [#1206](https://github.com/apache/arrow-go/pull/1206)
- Added `list_element`, `cumulative_sum`, `cumulative_sum_checked`, and `dictionary_encode` compute functions [#1138](https://github.com/apache/arrow-go/pull/1138),
[#1139](https://github.com/apache/arrow-go/pull/1139), [#1140](https://github.com/apache/arrow-go/pull/1140)
- Added `ValueAsAny` for accessing Arrow array values as native Go values [#1170](https://github.com/apache/arrow-go/pull/1170)
- Strengthened IPC file validation for malformed block framing and lengths [#1097](https://github.com/apache/arrow-go/pull/1097)

#### Bug Fixes
- Fixed a memory leak when calling `Resize(0)` on non-empty builders [#995](https://github.com/apache/arrow-go/pull/995)
- Preserved exact precision when casting strings to Decimal128 and Decimal256 scalars [#1107](https://github.com/apache/arrow-go/pull/1107)

#### Performance Improvements

This is a performance-heavy release: 32 of the merged pull requests are dedicated
optimizations. Unless noted otherwise, the figures below are the PR-reported
benchmarks on an Apple M1 Pro, comparing the new path against the scalar
baseline it replaces.

- Expanded SIMD acceleration for compute arithmetic, comparisons, and filtering on ARM64 and AMD64. Arithmetic kernels run 4.1-4.4x faster on int64 and float64
adds, int64 array/array comparisons drop from 313.6us to 29.3us per op (10.7x), narrow 8- and 16-bit integer comparisons reach 12.8-15.1x, and null-free
32-bit fixed-width filters compress up to 11.8x faster on 1M-element inputs [#1265](https://github.com/apache/arrow-go/pull/1265), [#1266](https://github.com/apache/arrow-go/pull/1266),
[#1284](https://github.com/apache/arrow-go/pull/1284), [#1286](https://github.com/apache/arrow-go/pull/1286), [#1287](https://github.com/apache/arrow-go/pull/1287), [#1288](https://github.com/apache/arrow-go/pull/1288)
- Building take indices from fragmented selection vectors is no longer quadratic. For a 1M-element alternating filter it drops from 4.31s to 515us, and a
serial `FilterRecordBatch` over the same filter falls from 2.06s to 831us [#1287](https://github.com/apache/arrow-go/pull/1287)
- Added SIMD-accelerated packing of boolean slices and validity data into Arrow bitmaps: `BooleanBuilder` packing of 65,536 values improves roughly 4-5x
(23.4us to 3.9us), batched validity packing is up to 4.4x faster, and ARM64 NEON bitmap operations gain 2.2-2.9x [#1283](https://github.com/apache/arrow-go/pull/1283),
[#1185](https://github.com/apache/arrow-go/pull/1185), [#1264](https://github.com/apache/arrow-go/pull/1264), [#1090](https://github.com/apache/arrow-go/pull/1090)
- Batched run-end encoded appends turn a millisecond-scale operation into a microsecond-scale one for null and empty-value runs, cutting 1.16MB across 55
allocations per op down to 1.7KB across 19 [#1214](https://github.com/apache/arrow-go/pull/1214)
- Concatenation avoids temporary buffers and copies bitmaps directly: 65,536 int64 values spread over 8,192 chunks go from 571.7us to 214.5us (-62%) with
allocations falling from 8,199 to 6 per op [#1194](https://github.com/apache/arrow-go/pull/1194), [#1224](https://github.com/apache/arrow-go/pull/1224)
- Serial and small-batch execution skips goroutine and span overhead: single-span kernel dispatch nearly halves latency at length 1 (342.0ns to 189.0ns),
serial record filtering over 128 columns goes from 709.8us to 420.9us, and serial `Take` plus IPC encoder scratch reuse cut per-op allocations across the
board [#1233](https://github.com/apache/arrow-go/pull/1233), [#1245](https://github.com/apache/arrow-go/pull/1245), [#1226](https://github.com/apache/arrow-go/pull/1226), [#1221](https://github.com/apache/arrow-go/pull/1221)
- CSV writing no longer materializes rows first, cutting a 1,000-row by 16-column write from 4.78ms to 0.84ms (-82%) and allocated bytes by 81% [#1190](https://github.com/apache/arrow-go/pull/1190)

### Parquet

#### Features

- Added read and write support for GeoArrow extension types using Parquet geometry and geography logical types [#960](https://github.com/apache/arrow-go/pull/960),
[#969](https://github.com/apache/arrow-go/pull/969)
- Added codec-aware dictionary cost fallback and per-column writer controls [#1036](https://github.com/apache/arrow-go/pull/1036)

#### Bug Fixes

- Correctly populated Bloom filters from dictionary-encoded values [#1164](https://github.com/apache/arrow-go/pull/1164)
- Rejected decimal values that overflow Parquet INT32 or INT64 columns instead of silently narrowing them [#1122](https://github.com/apache/arrow-go/pull/1122),
[#1161](https://github.com/apache/arrow-go/pull/1161)
- Fixed reading fixed-size lists whose parent values are null [#1099](https://github.com/apache/arrow-go/pull/1099)

#### Performance Improvements

- Added SIMD `BYTE_STREAM_SPLIT` encoding on ARM64 and AMD64: 16.9x faster for 4-byte values (113,877ns to 6,745ns per op) and 7.6x for 8-byte values [#1260](https://github.com/apache/arrow-go/pull/1260)
- Boolean decoding now targets Arrow bitmaps directly. All-true RLE boolean pages of 1M values decode in 2.45us instead of 2.65ms, and dense boolean column
reads through pqarrow drop 90% in time and 65% in heap use [#1246](https://github.com/apache/arrow-go/pull/1246), [#1182](https://github.com/apache/arrow-go/pull/1182)
- Batched encoding and decoding across the core codecs: plain `BYTE_ARRAY` encoding is 45-62% faster, RLE level encoding is 79% faster for all-defined
levels, and `DELTA_BINARY_PACKED` decoding is 34-66% faster [#1193](https://github.com/apache/arrow-go/pull/1193), [#1177](https://github.com/apache/arrow-go/pull/1177), [#1169](https://github.com/apache/arrow-go/pull/1169)
- Dictionary encoding allocates far less: numeric insertion of 65,535 float32 values goes from 64,905 allocations per op to 13, and typed byte-array memo
insertion cuts time 24% and allocations 50% (Apple M3 Max). Fixed-width dictionary materialization is also vectorized on AVX2 systems [#1178](https://github.com/apache/arrow-go/pull/1178),
[#1272](https://github.com/apache/arrow-go/pull/1272), [#1269](https://github.com/apache/arrow-go/pull/1269)
- Reduced copying when writing binary and fixed-size binary Arrow values to Parquet: 16-byte `FixedSizeBinary` writes are 72% faster for required columns
with statistics disabled, and 64K String writes go from 1.798ms to 1.260ms [#1262](https://github.com/apache/arrow-go/pull/1262), [#1263](https://github.com/apache/arrow-go/pull/1263)
- Compressors are reused across pages: random 64KiB gzip page encoding is 6.1x faster (94.7us to 15.6us) with allocations down from 15 to 1 per op, and
Brotli encoding drops from about 22 allocations per op to 1 [#1238](https://github.com/apache/arrow-go/pull/1238), [#1254](https://github.com/apache/arrow-go/pull/1254)
- Serial reads skip goroutine orchestration, trimming 18% from single-column row-group reads [#1235](https://github.com/apache/arrow-go/pull/1235)
